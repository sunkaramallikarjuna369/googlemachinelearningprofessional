1.2 Defining Success Metrics

Why Metrics Matter

Success metrics help you:

  • Measure if your ML solution is working
  • Compare different models objectively
  • Communicate results to stakeholders
  • Decide when to retrain or update models

Classification Metrics

Confusion Matrix

The foundation for understanding classification performance:

Predicted
Positive Negative
Actual Positive True Positive (TP) False Negative (FN)
Negative False Positive (FP) True Negative (TN)
Accuracy

Accuracy = (TP + TN) / (TP + TN + FP + FN)

When to use: Balanced datasets where all classes are equally important

Caution: Misleading with imbalanced data (e.g., 99% negative class)

Precision

Precision = TP / (TP + FP)

Meaning: Of all positive predictions, how many were actually positive?

When to use: When false positives are costly (e.g., spam filter - don't want to mark important emails as spam)

Recall (Sensitivity)

Recall = TP / (TP + FN)

Meaning: Of all actual positives, how many did we correctly identify?

When to use: When false negatives are costly (e.g., disease detection - don't want to miss sick patients)

F1 Score

F1 = 2 × (Precision × Recall) / (Precision + Recall)

Meaning: Harmonic mean of precision and recall

When to use: When you need a balance between precision and recall

AUC-ROC

Meaning: Area Under the Receiver Operating Characteristic Curve

Range: 0.5 (random) to 1.0 (perfect)

When to use: Comparing models across different thresholds, imbalanced datasets

Example: Fraud Detection

Scenario: Bank wants to detect fraudulent transactions

Dataset: 1% fraudulent, 99% legitimate transactions

Why accuracy is misleading:

A model that predicts "legitimate" for everything would have 99% accuracy but catch zero fraud!

Better metrics:

  • Recall: We want to catch as many fraudulent transactions as possible (minimize false negatives)
  • Precision: But we also don't want to block too many legitimate transactions (minimize false positives)
  • F1 Score: Balance between catching fraud and not annoying customers

Regression Metrics

Mean Absolute Error (MAE)

MAE = (1/n) × Σ|actual - predicted|

Meaning: Average absolute difference between predictions and actual values

Pros: Easy to interpret, same units as target variable

Cons: Doesn't penalize large errors more than small ones

Mean Squared Error (MSE)

MSE = (1/n) × Σ(actual - predicted)²

Meaning: Average squared difference between predictions and actual values

Pros: Penalizes large errors more heavily

Cons: Units are squared, harder to interpret

Root Mean Squared Error (RMSE)

RMSE = √MSE

Meaning: Square root of MSE

Pros: Same units as target variable, penalizes large errors

Most common: Used in many ML competitions and real-world applications

R² (R-squared)

R² = 1 - (SS_res / SS_tot)

Meaning: Proportion of variance explained by the model

Range: 0 to 1 (higher is better)

Interpretation: R² = 0.85 means model explains 85% of variance in data

Business Metrics vs ML Metrics

Business Metric ML Metric Example
Revenue increase Click-through rate (CTR) Recommendation system
Customer satisfaction Precision, Recall Search results quality
Cost reduction False positive rate Fraud detection
User engagement AUC-ROC Content personalization

Key Insight: Always connect ML metrics to business outcomes. A model with 95% accuracy might not be useful if it doesn't improve the business metric that matters.

1.3 Data Requirements and Availability

How Much Data Do You Need?

Simple Linear Models

Amount: Hundreds to thousands of examples

Example: Linear regression, logistic regression

Rule of thumb: 10× examples per feature

Tree-Based Models

Amount: Thousands to tens of thousands

Example: Random Forest, Gradient Boosting

Rule of thumb: More data = better, but diminishing returns

Deep Learning

Amount: Tens of thousands to millions

Example: Neural networks, CNNs, RNNs

Rule of thumb: More parameters = more data needed

Transfer Learning

Amount: Hundreds to thousands (much less!)

Example: Fine-tuning pre-trained models

Benefit: Leverage existing knowledge from large datasets

Data Quality Checklist

✅ Before Starting Your ML Project
  • Availability: Do you have access to the data you need?
  • Quantity: Do you have enough examples for your problem type?
  • Quality: Is the data accurate and reliable?
  • Completeness: Are there missing values? How many?
  • Relevance: Does the data contain signals related to your target?
  • Recency: Is the data up-to-date and representative?
  • Labels: For supervised learning, do you have labeled data?
  • Bias: Does the data represent all groups fairly?
  • Privacy: Can you legally use this data? (GDPR, CCPA, etc.)
  • Cost: What's the cost of collecting and storing this data?

Handling Data Limitations

Limited Labeled Data

Solutions:

  • Semi-supervised learning
  • Active learning (label most informative examples)
  • Transfer learning
  • Data augmentation
  • Synthetic data generation
Imbalanced Data

Solutions:

  • Oversampling minority class (SMOTE)
  • Undersampling majority class
  • Class weights in loss function
  • Ensemble methods
  • Anomaly detection approaches
Missing Data

Solutions:

  • Imputation (mean, median, mode)
  • Forward/backward fill (time series)
  • ML-based imputation
  • Create "missing" indicator feature
  • Remove rows/columns if <5% missing
Noisy Data

Solutions:

  • Outlier detection and removal
  • Smoothing techniques
  • Ensemble methods (robust to noise)
  • Regularization
  • Data validation pipelines

Question 1: Your company wants to predict customer churn. You have 100,000 customers, but only 2% have churned. What metric should you prioritize?

Show Answer

Answer: Recall (or F1 Score)

Explanation: With only 2% churn, accuracy would be misleading (98% accuracy by predicting "no churn" for everyone). You want to catch as many churning customers as possible (high recall), while also not annoying too many loyal customers with retention offers (reasonable precision). F1 Score balances both.

Question 2: You're building a house price prediction model. Which type of ML problem is this?

Show Answer

Answer: Regression

Explanation: House prices are continuous numerical values, making this a regression problem. You're predicting a number (price) rather than a category.

Question 3: Your fraud detection model has 95% precision and 60% recall. What does this mean for your business?

Show Answer

Answer: The model is very accurate when it flags fraud (95% of flagged transactions are actually fraudulent), but it's missing 40% of fraudulent transactions.

Explanation: High precision means few false alarms (good for customer experience), but low recall means you're letting significant fraud through (bad for business). You might want to adjust the threshold to increase recall, accepting some decrease in precision.

from google.cloud import aiplatform

# Initialize Vertex AI
aiplatform.init(project='my-project', location='us-central1')

# Create a custom training job
job = aiplatform.CustomTrainingJob(
    display_name='my-training-job',
    script_path='train.py',
    container_uri='gcr.io/cloud-aiplatform/training/tf-cpu.2-8:latest',
    requirements=['pandas', 'scikit-learn'],
    model_serving_container_image_uri='gcr.io/cloud-aiplatform/prediction/tf2-cpu.2-8:latest'

# Run the training job
model = job.run(
    dataset=my_dataset,
    replica_count=1,
    machine_type='n1-standard-4',
    training_fraction_split=0.8,
    validation_fraction_split=0.1,
    test_fraction_split=0.1
)

2.3 ML Architecture Patterns

Batch Prediction Architecture

When to use: Predictions don't need to be real-time, can be pre-computed

Typical Flow:
  1. Data stored in BigQuery or Cloud Storage
  2. Scheduled job (Cloud Scheduler) triggers batch prediction
  3. Vertex AI Batch Prediction processes all records
  4. Results written back to BigQuery or Cloud Storage
  5. Application reads pre-computed predictions
Advantages:
  • Cost-effective (process in bulk)
  • Can use larger, more complex models
  • Easier to optimize throughput
  • No latency requirements
Disadvantages:
  • Predictions may be stale
  • Can't handle new data immediately
  • Requires storage for all predictions
Example Use Cases:
  • Daily customer churn predictions
  • Weekly product recommendations
  • Monthly credit risk scoring
  • Nightly image classification for catalog

Online Prediction Architecture

When to use: Need real-time predictions with low latency

Typical Flow:
  1. User request comes to application
  2. Application calls Vertex AI Prediction endpoint
  3. Model returns prediction in real-time (< 1 second)
  4. Application uses prediction in response
Advantages:
  • Always up-to-date predictions
  • Can use latest user context
  • No need to store predictions
  • Handles new data immediately
Disadvantages:
  • Higher cost per prediction
  • Latency requirements limit model complexity
  • Need to handle traffic spikes
  • Requires always-on infrastructure
Example Use Cases:
  • Fraud detection during transaction
  • Real-time product recommendations
  • Content moderation
  • Chatbot responses
Best Practices for Online Predictions:
  • Use model caching: Cache frequently used features
  • Optimize model size: Smaller models = lower latency
  • Set up autoscaling: Handle traffic variations
  • Monitor latency: Set SLAs and alerts
  • Use prediction batching: Group multiple predictions when possible

Streaming ML Architecture

When to use: Process continuous data streams with ML

Typical Flow:
  1. Events published to Pub/Sub
  2. Dataflow processes stream with feature engineering
  3. Enriched features sent to ML model
  4. Predictions written to downstream systems (BigQuery, Bigtable, Pub/Sub)
  5. Real-time dashboards or alerts triggered
Example Use Cases:
  • IoT sensor anomaly detection
  • Real-time clickstream analysis
  • Live video content moderation
  • Financial market predictions

Hybrid Architecture (Batch + Online)

When to use: Combine benefits of both approaches

Common Pattern:
  1. Batch component: Pre-compute expensive features or embeddings
  2. Store in Bigtable/Redis: Fast feature lookup
  3. Online component: Combine pre-computed features with real-time context
  4. Make prediction: Fast inference with enriched features
Example: Recommendation System
  • Batch: Compute user embeddings and item similarities daily
  • Store: Save embeddings in Bigtable for fast lookup
  • Online: Fetch user embedding + current context (time, location)
  • Predict: Generate personalized recommendations in real-time

Benefit: Low latency (no need to compute embeddings in real-time) + fresh context

3.2 Data Preprocessing

Handling Missing Values

1. Remove Missing Data

When: Small percentage of missing values (< 5%)

import pandas as pd

# Remove rows with any missing values
df_clean = df.dropna()

# Remove rows where specific column is missing
df_clean = df.dropna(subset=['important_column'])
2. Imputation

When: Moderate missing values, want to preserve data

from sklearn.impute import SimpleImputer

# Mean imputation for numerical features
imputer = SimpleImputer(strategy='mean')
df['age'] = imputer.fit_transform(df[['age']])

# Mode imputation for categorical features
imputer = SimpleImputer(strategy='most_frequent')
df['category'] = imputer.fit_transform(df[['category']])

# Median imputation (robust to outliers)
imputer = SimpleImputer(strategy='median')
df['income'] = imputer.fit_transform(df[['income']])
3. Advanced Imputation

When: Complex patterns, multiple correlated features

from sklearn.experimental import enable_iterative_imputer
from sklearn.impute import IterativeImputer

# Iterative imputation (models each feature with missing values)
imputer = IterativeImputer(random_state=0)
df_imputed = imputer.fit_transform(df)

Handling Outliers

1. Statistical Methods
import numpy as np

# Z-score method (remove values > 3 standard deviations)
z_scores = np.abs((df['value'] - df['value'].mean()) / df['value'].std())
df_no_outliers = df[z_scores < 3]

# IQR method (Interquartile Range)
Q1 = df['value'].quantile(0.25)
Q3 = df['value'].quantile(0.75)
IQR = Q3 - Q1
df_no_outliers = df[(df['value'] >= Q1 - 1.5*IQR) & 
                     (df['value'] <= Q3 + 1.5*IQR)]
2. Capping/Winsorizing

Better than removal: Preserves data points

# Cap at 1st and 99th percentiles
lower = df['value'].quantile(0.01)
upper = df['value'].quantile(0.99)
df['value_capped'] = df['value'].clip(lower, upper)

Data Normalization and Scaling

StandardScaler (Z-score normalization)

Formula: (x - mean) / std

Result: Mean = 0, Std = 1

Use when: Features have different scales, using algorithms sensitive to scale (SVM, neural networks)

from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
X_scaled = scaler.fit_transform(X_train)
X_test_scaled = scaler.transform(X_test)  # Use same scaler!
MinMaxScaler

Formula: (x - min) / (max - min)

Result: Values between 0 and 1

Use when: Need bounded values, neural networks with sigmoid/tanh

from sklearn.preprocessing import MinMaxScaler

scaler = MinMaxScaler()
X_scaled = scaler.fit_transform(X_train)
RobustScaler

Formula: Uses median and IQR instead of mean and std

Use when: Data has outliers (more robust)

from sklearn.preprocessing import RobustScaler

scaler = RobustScaler()
X_scaled = scaler.fit_transform(X_train)
⚠️ Critical: Fit on Training Data Only!

Always fit scalers on training data, then transform both train and test:

# ✅ CORRECT
scaler.fit(X_train)
X_train_scaled = scaler.transform(X_train)
X_test_scaled = scaler.transform(X_test)

# ❌ WRONG - causes data leakage!
scaler.fit(X)  # Don't fit on all data
X_scaled = scaler.transform(X)

3.5 Practice Questions

Question 1:

You have a dataset with 20% missing values in the 'income' column. The data is not missing at random - higher income individuals are less likely to report. What's the best approach?

Answer: Use a separate "missing" indicator + imputation

Reasoning:

  • Missing data is informative (not random) - missingness itself is a signal
  • Create a binary feature: is_income_missing
  • Then impute the missing values (median is robust)
  • Model can learn from both the imputed value and the missingness pattern
df['is_income_missing'] = df['income'].isna().astype(int)
df['income'].fillna(df['income'].median(), inplace=True)

Question 2:

You're building a model to predict customer churn. You have customer IDs, which are unique identifiers. Should you include customer ID as a feature?

Answer: No, remove customer ID

Reasoning:

  • Customer ID is a unique identifier with no predictive power
  • Including it can cause overfitting (model memorizes IDs)
  • Won't generalize to new customers

Exception: If customer ID encodes information (e.g., ID format indicates signup channel), extract that information as a separate feature, then drop the ID

Question 3:

You need to scale features for a neural network. Your data has outliers. Which scaler should you use?

Answer: RobustScaler

Reasoning:

  • RobustScaler uses median and IQR (not affected by outliers)
  • StandardScaler uses mean and std (sensitive to outliers)
  • MinMaxScaler is also sensitive to outliers (uses min/max)

Alternative: Remove/cap outliers first, then use StandardScaler or MinMaxScaler

Question 4:

You're predicting stock prices using historical data. How should you split your data for training and testing?

Answer: Time-based split (chronological)

Reasoning:

  • Time-series data has temporal dependencies
  • Random split would leak future information into training
  • Must train on past, test on future to simulate real-world scenario
# Sort by date
df = df.sort_values('date')

# Split: train on 2020-2023, test on 2024
train = df[df['date'] < '2024-01-01']
test = df[df['date'] >= '2024-01-01']

⚠️ Never use random split for time-series data!

4.1 Algorithm Selection

Choosing the Right Algorithm

Linear Models

Algorithms: Linear Regression, Logistic Regression, Ridge, Lasso

Best for:

  • Linear relationships
  • High interpretability needed
  • Small to medium datasets
  • Fast training required

Pros: Fast, interpretable, low overfitting risk

Cons: Can't capture complex patterns

Tree-Based Models

Algorithms: Decision Trees, Random Forest, XGBoost, LightGBM

Best for:

  • Tabular data
  • Non-linear relationships
  • Mixed feature types
  • Feature importance needed

Pros: Handle non-linearity, robust to outliers, no scaling needed

Cons: Can overfit (single trees), computationally expensive (ensembles)

Neural Networks

Algorithms: MLP, CNN, RNN, Transformers

Best for:

  • Large datasets (millions of examples)
  • Complex patterns
  • Images, text, audio
  • Transfer learning available

Pros: Can learn any function, state-of-the-art for many tasks

Cons: Need lots of data, slow training, hard to interpret

Support Vector Machines (SVM)

Best for:

  • Small to medium datasets
  • High-dimensional data
  • Clear margin of separation

Pros: Effective in high dimensions, memory efficient

Cons: Slow for large datasets, sensitive to feature scaling

Decision Tree for Algorithm Selection

  1. What type of data?
    • Images: CNN (ResNet, EfficientNet) or Vision Transformer
    • Text: Transformers (BERT, T5) or RNN
    • Tabular: XGBoost, LightGBM, or Neural Networks
    • Time Series: ARIMA, LSTM, or Prophet
  2. How much data?
    • < 1K examples: Linear models, simple trees
    • 1K - 100K: Random Forest, XGBoost
    • > 100K: Neural networks, deep learning
  3. Interpretability required?
    • Yes: Linear models, Decision Trees, SHAP values
    • No: Any model (optimize for performance)
  4. Training time constraints?
    • Fast: Linear models, simple trees
    • Moderate: Random Forest, XGBoost
    • Slow OK: Neural networks, hyperparameter tuning

4.4 Handling Common ML Issues

Overfitting

Symptoms: High training accuracy, low validation/test accuracy

Solutions:
1. Get More Data

More training examples help model generalize better

2. Data Augmentation
# For images
from tensorflow.keras.preprocessing.image import ImageDataGenerator

datagen = ImageDataGenerator(
    rotation_range=20,
    width_shift_range=0.2,
    height_shift_range=0.2,
    horizontal_flip=True,
    zoom_range=0.2
)
3. Regularization
# L1 (Lasso) - feature selection
from sklearn.linear_model import Lasso
model = Lasso(alpha=0.1)

# L2 (Ridge) - shrink coefficients
from sklearn.linear_model import Ridge
model = Ridge(alpha=1.0)

# Elastic Net - combination of L1 and L2
from sklearn.linear_model import ElasticNet
model = ElasticNet(alpha=0.1, l1_ratio=0.5)
4. Dropout (Neural Networks)
from tensorflow.keras.layers import Dropout

model = Sequential([
    Dense(128, activation='relu'),
    Dropout(0.5),  # Drop 50% of neurons during training
    Dense(64, activation='relu'),
    Dropout(0.3),
    Dense(10, activation='softmax')
])
5. Early Stopping
from tensorflow.keras.callbacks import EarlyStopping

early_stop = EarlyStopping(
    monitor='val_loss',
    patience=10,  # Stop if no improvement for 10 epochs
    restore_best_weights=True
)

model.fit(X_train, y_train, 
          validation_data=(X_val, y_val),
          callbacks=[early_stop],
          epochs=100)
6. Reduce Model Complexity
  • Fewer layers in neural networks
  • Lower max_depth in trees
  • Fewer features (feature selection)

Underfitting

Symptoms: Low training accuracy, low validation accuracy

Solutions:
1. Increase Model Complexity
  • More layers/neurons in neural networks
  • Higher max_depth in trees
  • Polynomial features for linear models
2. Add More Features

Feature engineering to capture patterns

3. Reduce Regularization

Lower alpha in Ridge/Lasso, lower dropout rate

4. Train Longer

More epochs for neural networks, more estimators for ensembles

5. Try Different Algorithm

Switch from linear to non-linear model

Class Imbalance

Problem: One class has much more examples than others (e.g., 99% negative, 1% positive)

Solutions:
1. Resampling
from imblearn.over_sampling import SMOTE
from imblearn.under_sampling import RandomUnderSampler

# Oversample minority class (SMOTE)
smote = SMOTE(random_state=42)
X_resampled, y_resampled = smote.fit_resample(X_train, y_train)

# Undersample majority class
undersampler = RandomUnderSampler(random_state=42)
X_resampled, y_resampled = undersampler.fit_resample(X_train, y_train)
2. Class Weights
# Scikit-learn
from sklearn.ensemble import RandomForestClassifier
model = RandomForestClassifier(class_weight='balanced')

# XGBoost
import xgboost as xgb
scale_pos_weight = len(y_train[y_train==0]) / len(y_train[y_train==1])
model = xgb.XGBClassifier(scale_pos_weight=scale_pos_weight)

# TensorFlow/Keras
class_weights = {0: 1.0, 1: 10.0}  # Give 10x weight to minority class
model.fit(X_train, y_train, class_weight=class_weights)
3. Use Appropriate Metrics

Don't use accuracy! Use:

  • Precision, Recall, F1-Score
  • AUC-ROC
  • Precision-Recall curve
4. Anomaly Detection Approach

If extreme imbalance (< 1% positive), treat as anomaly detection

Training-Serving Skew

Problem: Model performs well in training but poorly in production due to data differences

Common Causes & Solutions:
1. Different Feature Engineering

Cause: Training uses different preprocessing than serving

Solution: Use same preprocessing code for both (TensorFlow Transform, Vertex AI Feature Store)

2. Data Distribution Shift

Cause: Production data differs from training data

Solution: Monitor data drift, retrain regularly with recent data

3. Missing Features at Serving Time

Cause: Features available in training but not in production

Solution: Only use features available at prediction time

4. Data Leakage

Cause: Training data includes information from the future

Solution: Use point-in-time features, proper train/test split
