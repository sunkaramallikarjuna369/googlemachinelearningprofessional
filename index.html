📋 Certification Overview

About the Exam

The Google Professional Machine Learning Engineer certification validates your ability to design, build, and productionize ML models to solve business challenges using Google Cloud technologies and knowledge of proven ML models and techniques.

Duration: 2 hours
Format: Multiple choice and multiple select
Cost: $200 USD
Language: English, Japanese

Who Should Take This Exam?

  • ML Engineers who want to validate their skills
  • Data Scientists transitioning to ML Engineering
  • Software Engineers moving into ML/AI
  • Anyone building production ML systems on Google Cloud

Prerequisites

  • 3+ years of industry experience (recommended)
  • 1+ years designing and managing solutions using Google Cloud
  • Understanding of ML fundamentals and algorithms
  • Experience with Python and ML frameworks (TensorFlow, scikit-learn, PyTorch)
  • Familiarity with data engineering concepts

1.1 Translating Business Problems to ML Problems

Understanding the Business Context

Before jumping into ML, you need to understand the business problem deeply:

Example: E-commerce Product Recommendations

Business Problem: "We want to increase sales by showing customers products they're likely to buy."

ML Translation:

  • Problem Type: Recommendation system (supervised learning)
  • Input: User browsing history, purchase history, product features, user demographics
  • Output: Ranked list of product recommendations
  • Success Metric: Click-through rate (CTR), conversion rate, revenue per user

When to Use ML vs Traditional Programming

Use ML When... Use Traditional Programming When...
Rules are complex and hard to code Rules are simple and well-defined
Patterns exist in data No historical data available
Problem requires adaptation over time Problem is static and unchanging
Scale is large (millions of examples) Scale is small (hundreds of examples)
Human expertise is hard to codify Expert rules can be easily written

1.2 Defining Success Metrics

Why Metrics Matter

Success metrics help you:

  • Measure if your ML solution is working
  • Compare different models objectively
  • Communicate results to stakeholders
  • Decide when to retrain or update models

Classification Metrics

Confusion Matrix

The foundation for understanding classification performance:

Predicted
Positive Negative
Actual Positive True Positive (TP) False Negative (FN)
Negative False Positive (FP) True Negative (TN)
Accuracy

Accuracy = (TP + TN) / (TP + TN + FP + FN)

When to use: Balanced datasets where all classes are equally important

Caution: Misleading with imbalanced data (e.g., 99% negative class)

Precision

Precision = TP / (TP + FP)

Meaning: Of all positive predictions, how many were actually positive?

When to use: When false positives are costly (e.g., spam filter - don't want to mark important emails as spam)

Recall (Sensitivity)

Recall = TP / (TP + FN)

Meaning: Of all actual positives, how many did we correctly identify?

When to use: When false negatives are costly (e.g., disease detection - don't want to miss sick patients)

F1 Score

F1 = 2 × (Precision × Recall) / (Precision + Recall)

Meaning: Harmonic mean of precision and recall

When to use: When you need a balance between precision and recall

AUC-ROC

Meaning: Area Under the Receiver Operating Characteristic Curve

Range: 0.5 (random) to 1.0 (perfect)

When to use: Comparing models across different thresholds, imbalanced datasets

Example: Fraud Detection

Scenario: Bank wants to detect fraudulent transactions

Dataset: 1% fraudulent, 99% legitimate transactions

Why accuracy is misleading:

A model that predicts "legitimate" for everything would have 99% accuracy but catch zero fraud!

Better metrics:

  • Recall: We want to catch as many fraudulent transactions as possible (minimize false negatives)
  • Precision: But we also don't want to block too many legitimate transactions (minimize false positives)
  • F1 Score: Balance between catching fraud and not annoying customers

Regression Metrics

Mean Absolute Error (MAE)

MAE = (1/n) × Σ|actual - predicted|

Meaning: Average absolute difference between predictions and actual values

Pros: Easy to interpret, same units as target variable

Cons: Doesn't penalize large errors more than small ones

Mean Squared Error (MSE)

MSE = (1/n) × Σ(actual - predicted)²

Meaning: Average squared difference between predictions and actual values

Pros: Penalizes large errors more heavily

Cons: Units are squared, harder to interpret

Root Mean Squared Error (RMSE)

RMSE = √MSE

Meaning: Square root of MSE

Pros: Same units as target variable, penalizes large errors

Most common: Used in many ML competitions and real-world applications

R² (R-squared)

R² = 1 - (SS_res / SS_tot)

Meaning: Proportion of variance explained by the model

Range: 0 to 1 (higher is better)

Interpretation: R² = 0.85 means model explains 85% of variance in data

Business Metrics vs ML Metrics

Business Metric ML Metric Example
Revenue increase Click-through rate (CTR) Recommendation system
Customer satisfaction Precision, Recall Search results quality
Cost reduction False positive rate Fraud detection
User engagement AUC-ROC Content personalization

Key Insight: Always connect ML metrics to business outcomes. A model with 95% accuracy might not be useful if it doesn't improve the business metric that matters.

1.3 Data Requirements and Availability

How Much Data Do You Need?

Simple Linear Models

Amount: Hundreds to thousands of examples

Example: Linear regression, logistic regression

Rule of thumb: 10× examples per feature

Tree-Based Models

Amount: Thousands to tens of thousands

Example: Random Forest, Gradient Boosting

Rule of thumb: More data = better, but diminishing returns

Deep Learning

Amount: Tens of thousands to millions

Example: Neural networks, CNNs, RNNs

Rule of thumb: More parameters = more data needed

Transfer Learning

Amount: Hundreds to thousands (much less!)

Example: Fine-tuning pre-trained models

Benefit: Leverage existing knowledge from large datasets

Data Quality Checklist

✅ Before Starting Your ML Project
  • Availability: Do you have access to the data you need?
  • Quantity: Do you have enough examples for your problem type?
  • Quality: Is the data accurate and reliable?
  • Completeness: Are there missing values? How many?
  • Relevance: Does the data contain signals related to your target?
  • Recency: Is the data up-to-date and representative?
  • Labels: For supervised learning, do you have labeled data?
  • Bias: Does the data represent all groups fairly?
  • Privacy: Can you legally use this data? (GDPR, CCPA, etc.)
  • Cost: What's the cost of collecting and storing this data?

Handling Data Limitations

Limited Labeled Data

Solutions:

  • Semi-supervised learning
  • Active learning (label most informative examples)
  • Transfer learning
  • Data augmentation
  • Synthetic data generation
Imbalanced Data

Solutions:

  • Oversampling minority class (SMOTE)
  • Undersampling majority class
  • Class weights in loss function
  • Ensemble methods
  • Anomaly detection approaches
Missing Data

Solutions:

  • Imputation (mean, median, mode)
  • Forward/backward fill (time series)
  • ML-based imputation
  • Create "missing" indicator feature
  • Remove rows/columns if <5% missing
Noisy Data

Solutions:

  • Outlier detection and removal
  • Smoothing techniques
  • Ensemble methods (robust to noise)
  • Regularization
  • Data validation pipelines

📝 Practice Questions - Domain 1

Question 1: Your company wants to predict customer churn. You have 100,000 customers, but only 2% have churned. What metric should you prioritize?

Show Answer

Answer: Recall (or F1 Score)

Explanation: With only 2% churn, accuracy would be misleading (98% accuracy by predicting "no churn" for everyone). You want to catch as many churning customers as possible (high recall), while also not annoying too many loyal customers with retention offers (reasonable precision). F1 Score balances both.

Question 2: You're building a house price prediction model. Which type of ML problem is this?

Show Answer

Answer: Regression

Explanation: House prices are continuous numerical values, making this a regression problem. You're predicting a number (price) rather than a category.

Question 3: Your fraud detection model has 95% precision and 60% recall. What does this mean for your business?

Show Answer

Answer: The model is very accurate when it flags fraud (95% of flagged transactions are actually fraudulent), but it's missing 40% of fraudulent transactions.

Explanation: High precision means few false alarms (good for customer experience), but low recall means you're letting significant fraud through (bad for business). You might want to adjust the threshold to increase recall, accepting some decrease in precision.
